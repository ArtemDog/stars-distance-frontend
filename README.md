# Лабораторная работа №5 — Базовое SPA на React + TypeScript

## Краткое описание
В этой работе вы разрабатываете одностраничное приложение (SPA) на React и TypeScript с использованием Vite. Приложение показывает три страницы: главную (статическое описание), страницу списка услуг (с фильтрами) и страницу детали одной услуги. Данные должны подгружаться из веб‑сервиса; при отсутствии доступа к бэкенду приложение использует локальные mock-данные.

Проект использует React-Bootstrap для базовых компонентов интерфейса, собственную реализацию breadcrumbs и navbar. Redux и Context использоваться не должны.

## Цель работы
- Разработать базовый SPA на React/TS, подключить его к веб‑сервису.
- Сделать три страницы: главная (статическое содержимое), список услуг (с фильтрами) и страница детали.
- Реализовать фильтрацию по диапазону дат, названию и цене — на стороне бэкенда (параметры запроса).
- Предусмотреть fallback на mock-объекты, если бэкенд недоступен.

## Структура репозитория (основное)
- `src/pages/` — страницы приложения: `HomePage.tsx`, `StarsListPage.tsx`, `StarPage.tsx`.
- `src/components/` — переиспользуемые компоненты: `Navigation.tsx`, `BreadCrumbs.tsx`, `InputField.tsx`, `StarCard.tsx`, `StarBackground.tsx`.
- `src/modules/` — логика работы с данными: `starsApi.ts` (fetch к бэкенду), `mock.ts` (локальные данные для fallback).

## Что реализовано (функциональные требования)
- Навигационная панель (navbar) с переходом между страницами.
- Хлебные крошки (breadcrumbs) — самописная навигационная цепочка.
- Страница списка услуг со всеми фильтрами: диапазон дат, название, цена.
- Фильтрация выполняется на бэкенде (параметры в URL запроса). Фронтенд формирует запрос и отображает результат.
- Карточки услуг (`StarCard`) отображают изображение; если поле изображения пустой — показывается изображение по умолчанию.
- Ajax-запросы выполнены вручную через `fetch`. При проблемах с CORS используется проксирование запросов через Vite (dev proxy).

## Как запустить (локально)
Требования: node.js (рекомендуется 16+), npm или yarn.

1) Установите зависимости:

```powershell
npm install
# или
yarn
```

2) Запустить в режиме разработки (локальный dev-сервер Vite):

```powershell
npm run dev
# или
yarn dev
```

Vite поднимет dev‑сервер, фронтенд будет доступен по адресу, указанному в консоли (обычно http://localhost:5173).

Примечание про proxy: если в `vite.config.ts` настроен прокси (например, `/api` -> `http://localhost:3000`), то все fetch-запросы к относительным путям `/api/...` будут проксироваться и CORS-проблемы убираются.

## Запуск с mock-данными (без бэкенда)
По умолчанию в `starsApi.ts` реализована логика: попытка сделать `fetch` к бэкенду; при ошибке (сеть недоступна или ответ не OK) — возвращается коллекция из `mock.ts`. Чтобы специально протестировать mock — отключите бэкенд и запустите dev-сервер.

## Запуск с бэкендом
1) Запустите ваш веб‑сервис (напр., на `http://localhost:3000`).
2) Убедитесь, что в `vite.config.ts` указан корректный прокси, связывающий, например, `/api` с `http://localhost:3000`.
3) В инструментах разработчика (Network) вы увидите, что `fetch` отправляется на относительный путь `/api/...` — Vite проксирует этот запрос на реальный адрес бэкенда.

Если изображения хранятся в MinIO, в ответах API должны приходить поля с именами файлов или URL-адресами в MinIO. Пример: `imageName: "products/12345.jpg"` и базовый адрес MinIO `https://minio.example.com/bucket/` — тогда полный URL будет собран фронтендом как `https://minio.example.com/bucket/products/12345.jpg`.

## Как проверить изменения в БД и их отображение во фронтенде
1) Через API бэкенда выполните изменение (POST/PUT/DELETE) — в зависимости от реализации сервиса.
2) На фронтенде обновите список услуг (перейдите на страницу списка или вызовите повторный fetch). Данные должны отобразиться согласно новому состоянию БД.

Если backend поддерживает WebSocket/Server-Sent Events — можно реализовать автообновление, но в рамках этой работы используется простая модель pull (fetch при загрузке/обновлении страницы).

## Пояснение ключевых компонентов и архитектуры

Contract (кратко):
- Вход: HTTP API (JSON) с коллекцией услуг; при недоступности API — локальный mock.
- Выход: Три страницы с элементами UI и фильтрацией.
- Ошибки: сетевые ошибки и неверный ответ API приводят к использованию mock-данных.

Компоненты и их роль:
- `StarsListPage.tsx` — страница списка: содержит состояние фильтров (useState), выполняет fetch данных при монтировании и при изменении фильтров (useEffect). Передаёт в `StarCard` данные каждой услуги.
- `StarCard.tsx` — карточка услуги: получает props (объект услуги) и отображает поля (название, цена, даты, изображение). Если `image` пустой — показывает placeholder.
- `InputField.tsx` — контролируемый input-компонент: получает `value`, `onChange` и label через props.
- `BreadCrumbs.tsx` — отображает путь к текущей странице; получает массив элементов через props.
- `Navigation.tsx` — navbar: навигация между базовыми страницами.
- `starsApi.ts` — модуль с функциями для вызова API: формирование URL с параметрами фильтрации, fetch + обработка ошибок, fallback на `mock.ts`.

Props и хуки (ключевые моменты):
- useState хранит локальные состояния — значения фильтров, список загруженных услуг, статус загрузки и ошибки.
- useEffect используется для загрузки данных при монтировании и при изменении фильтров: эффект зависим от массива фильтров и вызывает функцию загрузки данных.
- Вызовы fetch формируют query string, например: `/api/services?name=star&priceMin=10&priceMax=100&dateFrom=2025-01-01&dateTo=2025-12-31`.

Пример логики фильтрации (архитектурно):
1) Пользователь задаёт значения фильтров (компоненты ввода меняют локальный state).
2) Нажатие кнопки «Применить» или изменение поля вызывает effect, который собирает параметры и вызывает `starsApi.fetchServices(params)`.
3) `starsApi` делает fetch; если ответ 200 и JSON валиден — отдаёт данные; иначе — возвращает mock.

Edge cases (важные):
- Пустые/невалидные фильтры — не включать в query string.
- Большие наборы данных — реализовать пагинацию на бэкенде (если нужно).
- Частые запросы при вводе — debounce на вводе текста (опционально).

## Контрольные вопросы (короткие ответы)
- Что такое React, props и state?
	React — библиотека для построения UI; props — входные параметры компонента (readonly); state — внутреннее состояние компонента, меняющееся во времени.
- Чем компонент отличается от элемента?
	Элемент React — минимальная единица (результат вызова createElement/JSX). Компонент — функция/класс, возвращающая элемент(ы).
- Что делают useState и useEffect?
	useState — даёт локальное состояние; useEffect — выполняет побочные эффекты (загрузка данных, подписки) при монтировании/обновлении.
- Жизненный цикл компонента?
	Для функциональных компонентов: монтирование (initial render), обновления (при изменении state/props), размонтирование; useEffect покрывает эти стадии.
- Что такое CORS и обратный прокси?
	CORS — политика браузера, запрещающая кросс-доменные запросы без специальных заголовков; обратный прокси (например, Vite dev proxy) перенаправляет запросы с фронтенда на другой домен, избегая CORS в dev.
- Vite и Babel — почему нужен Vite?
	Vite — быстрый dev-сервер и сборщик для современных фронтенд-проектов; Babel — трансформер JS/TS (могут использоваться вместе, но Vite опирается на esbuild/rollup для скорости).
- BFF и GraphQL?
	BFF (Backend For Frontend) — слой, адаптирующий API под UI; GraphQL — альтернатива REST с единым endpoint и запросами по схеме.
- Next.js и SSG?
	Next.js — фреймворк для React; SSG (Static Site Generation) — генерация статичных страниц на этапе сборки.
- FSD?
	Feature-Sliced Design — методология организации кода по фичам и уровням абстракции.
